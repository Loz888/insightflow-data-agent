# 支持能力与拒绝边界

## 支持
15项原指标，加“已支付且已送达订单数”（配送事件先按订单去重）。
COUNT/SUM/AVG/MIN/MAX/比率；订单月份、多个离散月份、ISO日期区间、近N个完整UTC自然日。
业务参考时间由配置注入，默认2026-10-01 UTC；不拿数据最大日期冒充当前时间。
所有区间半开[start,end)，近30天指参考日之前30个完整UTC日，不含参考日。
跨月、跨年与闰年边界有独立时钟测试。
地区包含与排除集合；同一会话继承省略约束、明确条件覆盖、切换指标。
地区/月分组、商品主数据类别/商品分组、Top1至10及排序；订单商品分摊尚不支持。
单指标明确月环比，用两个已验证区间+compare工具计算；同比缺历史只能澄清。
空结果、NULL与0区分，分母0返回NULL，Decimal保存；金额不靠浮点凑结果。
退款采用原订单批次和成功退款口径，销售与退款预聚合避免fan-out。

## 数据版本
原v1-seed20261020五表及30题答案未改；订单覆盖2026-06-03至2026-10-01（半开）。
这是受控生成器覆盖，不是供应商真实经营周期。
V2.1仅新增配送/活动/营销日报/库存/报价五表和独立参考题，不改原五表行。
两份额外独立Seed101/202数据库改变客户/商品明细金额分布，用于复查错误SQL巧合正确的问题。
订单时间/状态模式仍共享生成逻辑，不能称为所有维度完全独立数据分布。
同一订单多配送事件专门验证去重；库存、营销、报价是有业务含义的干扰表。
数据版本应结合base seed、additional_manifest和schema_version读取。

## 必须澄清或拒绝
- 2026年9月订单数同比：没有2025年9月，不补零、不返回单月冒充同比。
- 未定义的相对对比、周末、工作日、支付方式、金额阈值、复合否定、其他时区/币种：澄清。
- 订单按商品类别退款归因、利润、因果、预测：口径缺失，澄清。
- “那第二个呢”：指代不清，澄清；失败历史不进入可信约束。
- 写SQL、系统表/文件/危险函数、未注册工具或越权run/session：拒绝。

## 语义校验的范围
模型产出QueryPlan；系统对明确日期、地区否定、指标、排序和对比做独立守卫。
模型生成SQL，再与受支持的关系/聚合契约比对；仅规范化已知的括号、UTC表示、主键计数和绑定别名等价。
可能误拒绝其他等价写法，真实实验已观察到；不宣称证明任意SQL等价或任意中文理解正确。
不能仅凭模型置信度、SQL可执行或Mock全绿判断业务正确。独立参考结果与多快照复查另行评分。
