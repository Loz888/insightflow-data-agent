# Context 专项与消融
ContextOnly/Full 保留权威结构化条件；Baseline/RetrievalOnly 不注入历史和旧约束。
上下文预算、历史上限和 Session 存储继续复用原实现，没有新增长期记忆或摘要模型。

真实 PostgreSQL 专项覆盖：
A 继承 2026-09 与退款订单率，并新增华东；
B 订单数“改成8月”覆盖旧月份；
C 华东退款订单率切换为退款金额率，保留地区且不混淆分子/分母；
D 不同 Session 的地区/月份隔离；
E 多轮增长后最多 4 次成功历史，Prompt 仍受估算 Token 预算；
F SQL 修正耗尽的失败轮不覆盖上次可信条件，下一次可继续原条件。
模糊“那第二个呢”请求澄清；元数据不存在或预算不足不编造业务事实。

四模式各 30 案例：有历史两组均 30/30，无历史两组均 25/30。
这是规则 Mock 真实消费权威状态的证据，不能当成真实 LLM 理解多轮上下文的成功率。
自然语言历史仅作为非权威数据；业务指标、日期、地区、币种独立保留。
工具输出优先裁剪，不能丢关键约束；裁剪无法容纳则 BUDGET_EXHAUSTED。
Context Token 仍是 UTF-8/3 估算，API Token Usage 在 Mock 中未知。

详细四模式结果、上下文大小、模型调用和延迟见 evaldata/ablation/report.md。
