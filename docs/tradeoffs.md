# 关键工程取舍

- 保留LangGraph单Agent：用显式状态与有界循环表达工具闭环；没有为名词增加多Agent。
- 结构化JSON action：统一服务端验证，便于协议故障测试；不是厂商原生tool_calls，可靠性仍受JSON输出影响。
- 保守SQL契约：优先拦截“安全却错义”的查询，接受误拒绝部分等价SQL的代价；不偷偷改用服务器模板生成真实SQL。
- 规则检索默认：真实10表测量中Precision最好且Recall不低；词法可解释但未胜出，暂不引入向量库。
- PostgreSQL控制面：复用已有组件，短事务租约/版本，避免网络调用期间持有连接；不引入Redis/Kafka/Kubernetes。
- 每进程并发+持久预算：简单可测试；不宣称分布式全局并发限流。多副本需明确配置总容量。
- 静态Bearer主体：满足最小认证/所有权；不是SSO。业务合成数据共享，不宣称RLS多租户。
- 控制数据与业务Reader分角色：模型和SQL不能接触运行库。迁移Owner仅用于启动/运维，不给Agent工具。
- 幂等不是Exactly-once：避免正常重放重复计费；崩溃后的外部调用可能已被供应商处理，保留未知消费并中断。
- 实测Usage结算保守上界：缺失Usage不能归零，应用预算不是供应商账单硬封顶。管理员改数据库/实验ID是信任边界。
- OpenTelemetry本地有界导出：验证了真实Span和关联，不冒称部署了外部Collector；持久事件另存PG。
- 简单页面：只做问题、会话、进度、SQL、证据和取消；不把时间投入装饰性前端。
- 新旧入口并存：默认serve为V2，V1只显式用于回归；旧结果和两轮真实性能失败不删除。
- 当前更可靠但更慢：HTTP对照显示控制面开销，后续可批量事件/减少数据库往返，需要单独性能任务验证。
