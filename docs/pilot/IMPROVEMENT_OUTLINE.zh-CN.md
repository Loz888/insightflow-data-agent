# InsightFlow 改进大纲

范围：基于现有 V2 与本地试点升级继续完善，不重写 Agent，不迁移已有实验账本，不覆盖历史评测。

## 已完成、继续保留

真实 Max 两轮代表集 25/30、27/30，定向复验 8/9 和最终 HTTP 4/4 已完成；原始题集、全部失败与共享费用账本继续保留。新试点能力的新环境回归为 332 PASS / 0 FAIL / 0 SKIP。后续真实验证仅针对新改动和剩余失败，不重复宣称“尚未做大模型测验”。

## P0：固定当前成果并补齐验收

- 对齐代码、README、配置、PROGRESS 和验收报告，记录实际源码清单及哈希；复用 fresh_verify、CI、现有单元/集成测试。
- 后续模型默认 Max，保留显式 High；模型强度、提示词版本、Schema 和数据快照进入新实验元数据。
- 最终快照执行必要回归、静态检查与秘密扫描；本地改动经检查后形成可追溯提交，不自动公开或推送。
- 退出条件：新配置与协议测试通过，最终版本有明确 PASS/FAIL/SKIP/BLOCKED 清单；历史数据与预算未改变。

## P1：提高真实分析正确率

- 先复用已有失败案例、独立参考 SQL 和数据快照，按问题理解、指标口径、SQL、答案引用分别归因。
- 优先修复聚合粒度、退款、零分母、日期、比较期和多轮条件继承；增加等价 SQL 的接受能力，同时保持权限与语义拒绝断言。
- 固定 Max 配置后进行分阶段真实评测；付费阶段仅在原授权和剩余共享预算内进行，不更换实验 ID 规避上限。
- 退出条件：支持范围内新旧案例可复现，没有安全拒绝回退；真实结果单独报告，不能用 Mock 正确率替代。

## P1：完善数据与生命周期边界

- 复用现有摘要 Token、身份作用域、FORCE RLS、只读角色和事务内租户上下文。
- 扩充撤销、跨租户、连接池复用、取消/删除/恢复竞争、备份恢复后的权限验证。
- 为事件、Checkpoint、结果制定可测试的保留、清理和容量策略；保留必要审计与费用记录，避免删除后恢复敏感信息。
- 付费请求恢复继续保守处理；在供应商结果无法确认时，不声称 Exactly-once，也不自动释放未知费用。

## P2：证明容量和运维能力

- 复用现有 HTTP 与持续运行脚本，补齐同一冻结版本的并发 1/4/8/16/32 对照；Mock 吞吐与真实模型延迟分开。
- 检查会话锁、数据库调用、连接池和事件写入开销，依据剖析结果优化；不先增加缓存或替换框架。
- 在可用容器环境验证部署、健康检查、限流、真实告警投递和备份恢复；报告本机边界，不虚构生产 SLA。

## P3：扩大业务与产品范围

- 先接入一个经授权的真实业务域，逐项登记指标、负责人、数据覆盖和权限。
- 展示 SQL、指标定义、证据、限制及澄清选项，再按实际需求接入企业身份服务。
- 多数据库、复杂归因与预测分别立项，不能以现有受控订单数据评测推导通用能力。

## 执行顺序

冻结成果 → 最终离线验收 → 高价值失败修复 → 预算内小批真实验证 → 性能与运维 → 扩展业务。
每一阶段复用原夹具与原始记录，采用新输出目录，仅在相关模块变化或存在未解失败时扩大测试。
